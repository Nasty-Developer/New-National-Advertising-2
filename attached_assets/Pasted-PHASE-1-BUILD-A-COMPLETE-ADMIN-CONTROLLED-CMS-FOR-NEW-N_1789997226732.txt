PHASE 1 — BUILD A COMPLETE ADMIN-CONTROLLED CMS FOR NEW NATIONAL ADVERTISING

We already have the New National Advertising website deployed on Render with a React/Vite frontend and a Node/Express backend.

IMPORTANT:
Do NOT redesign the project from scratch.
Do NOT remove any existing website data, services, machines, products, descriptions, images, contact information, routes, or existing functionality.
Preserve all existing content and migrate/structure it into the new admin-controlled system.

The objective of this phase is to make the Admin Panel the central CMS/control system for the entire website.

==================================================
1. MACHINES MANAGEMENT
==================================================

The Admin Panel must allow the administrator to:

- Add new machines
- Edit existing machines
- Delete machines only through an intentional admin action
- Change machine name
- Change machine short description
- Change machine full description/about information
- Change machine specifications
- Change machine features
- Change machine category/type
- Upload machine images
- Upload multiple images for one machine
- Replace existing images
- Delete individual machine images
- Reorder machine images
- Set a primary/cover image
- Publish/unpublish a machine
- Control display order

IMPORTANT:
All existing machine information must remain available.
Do NOT remove or simplify the existing machine data.

The four existing machines must remain available and editable from the Admin Panel.

Machine data currently includes:
- Epson SureColor S80670
- Wide-Format Roll Laminator
- Large-Format Printing Machine
- CO₂ Laser Cutting & Engraving Machine

Do not invent technical specifications where they are not already available.

==================================================
7. BACKEND REQUIREMENT
==================================================

Because the project is hosted on Render, properly handle the backend architecture.

Do NOT create fake frontend-only CRUD.

Admin changes must persist through the actual backend/database/storage architecture.

Make sure:

- API endpoints exist for machines
- API endpoints exist for products
- API endpoints exist for services
- API endpoints exist for website content
- API endpoints exist for contact numbers/settings
- Image uploads use persistent storage
- Admin authentication remains protected
- Admin-only operations are authorized server-side
- Frontend reads published content from the backend

Do not use temporary in-memory arrays for production data.

Do not create functionality that disappears after a Render restart/redeployment.

==================================================
8. DATA SAFETY
==================================================

VERY IMPORTANT:

DO NOT DELETE OR LOSE EXISTING DATA.

Before modifying the data architecture:

- Inspect the current project
- Inspect current database/storage structures
- Inspect existing machine/product/service data
- Preserve existing routes
- Preserve existing images
- Preserve existing content
- Migrate existing data safely if required

Do not replace existing data with placeholders.
