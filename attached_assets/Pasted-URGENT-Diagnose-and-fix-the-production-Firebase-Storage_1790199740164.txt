We have confirmed that the live production website works and admin authentication works, but BOTH:
1. New image uploads from the production admin panel fail with "Upload failed"
2. Existing product/machine images stored in Firebase Storage also fail to load on production

IMPORTANT EVIDENCE FROM CHROME NETWORK:

A failing image request is being sent to:

https://storage.googleapis.com/newnationaladv.firebasestorage.app/products/...

The signed URL contains:

X-Goog-Algorithm=GOOG4-RSA-SHA256
X-Goog-Credential=firebase-adminsdk-...
X-Goog-SignedHeaders=content-type%3Bhost
X-Goog-Date=...
X-Goog-Expires=900
X-Goog-Signature=...

This strongly suggests that our backend is generating Google Cloud Storage signed download URLs that include "content-type" in the signed headers.

For a normal browser GET request for an image, the browser may not send the exact Content-Type header that was included when the signed URL was generated, which can cause Google Cloud Storage to reject the request with a signed URL/signature mismatch or HTTP 403.

DO NOT GUESS. Inspect the actual implementation first.
